# Release Notes: BabeL-O v0.5.0

v0.5.0 is a minor release focused on **compaction correctness and opt-in
strategy experiments**. The default compaction path is still `stock`; the
adaptive, digest, summary-cache, cache-aware, faithful-digest, and retrieval
paths are experimental and must be enabled explicitly. This release does not
switch the default strategy.

## What Changed

1. **Compaction correctness fixes (default)**

   - Compaction now reads the newest event window instead of the oldest
     10,000 events, so sessions with long histories no longer lose the current
     instruction.
   - The current `user_message` is always retained; compaction fails closed if
     it cannot keep it.
   - Post-compact state and summary use separate budgets, so summary truncation
     cannot delete the state block.
   - The ledger records pre/post token counts in the same unit as the trigger
     and records summary usage.

2. **Opt-in adaptive compaction**

   - `BABEL_O_COMPACT_MODE=stock|noop|adaptive` (default `stock`).
   - Optional `BABEL_O_COMPACT_DECISION_LOG` JSONL ledger.
   - `adaptive` adds payback admission, a decision ledger, and opt-in T1
     reversible eviction (`BABEL_O_COMPACT_T1=1`).
   - Grounding is narrowed to SHA-backed authority; stock behavior is unchanged.

3. **Deterministic digest and cache mapping**

   - Adaptive compaction can use a structured digest instead of an LLM prose
     summary.
   - Summary budget scales with the context window.
   - Provider cache-token mapping is recorded for DeepSeek and OpenAI.
   - Optional `BABEL_O_COMPACT_BOUNDARY=tail` moves the boundary before the
     current instruction for prefix stability; stock stays `system`.

4. **Summary cache and payback feedback**

   - `BABEL_O_COMPACT_SUMMARY_CACHE=1` enables a bounded in-process summary
     cache.
   - `BABEL_O_COMPACT_SUMMARY_MODEL` overrides the summarizer model.
   - Realized payback feeds the adaptive admission policy.
   - `BABEL_O_COMPACT_FORCED_PERCENT` exists for forced-compaction experiments.

5. **Faithful digest (experimental)**

   - `BABEL_O_COMPACT_FAITHFUL_DIGEST=1` enables an extractive digest with
     verbatim anchors and no recursive compaction of a previous digest.
   - Works with `adaptive` or `stock` mode; stock without the flag is unchanged.
   - The cost benefit is not established; treat this as an experimental mode.

6. **Cache-aware thresholds (experimental)**

   - `BABEL_O_COMPACT_CACHE_AWARE=1` can raise the stock 90/70 thresholds when
     cache reuse is high.
   - Evaluation did not establish a cost win; it remains opt-in and is not a
     default-switch candidate.

7. **Retrieval prototype (experimental, not recommended)**

   - `BABEL_O_COMPACT_RETRIEVAL=1` replaces the summary with retrieval pointers.
   - The prototype is not recommended for production: the model frequently did
     not call `contextSearch`, and quality/cost results were not stable.

8. **Nexus port discovery and switching**

   - The launcher now verifies Nexus identity in `/health` instead of treating
     any 2xx `/health` response as Nexus.
   - When the requested port is occupied by a non-Nexus service, `bbl go`
     starts the managed Nexus on the next free neighbouring port and prints a
     notice.
   - `bbl go --nexus-port-scan-attempts <n>` bounds the local port scan.

9. **Evaluation-only provider entry**

   - The release includes an eval-only `kimi-coding/k3` provider/model entry
     used for compaction evaluation. It is not a default provider and carries
     no support commitment.

## Install

macOS and Linux:

```sh
curl -fsSL https://raw.githubusercontent.com/SuTang-vain/BabeL-O/main/scripts/install.sh | \
  BBL_VERSION=v0.5.0 bash
bbl go
```

Prerequisite: Node.js >= 22 on `PATH`. The portable package bundles the
matching Go TUI binary.

## Known Notes

- **Stock remains the default:** 90/70 compaction thresholds, prose summary,
  system boundary, and no retrieval.
- The P0 correctness fixes are active by default. The strategy flags are
  opt-in and experimental.
- Cache-aware and faithful-digest evaluation did not establish a default cost
  win; they remain opt-in. Retrieval is a prototype and is not recommended.
- The release does not claim that compaction saves tokens by default. Mixed
  and null results are intentionally reflected in the evaluation reports.
- The Kimi provider entry is for evaluation only; no model/provider support
  guarantee is implied.
- macOS/Linux portable assets are the primary install path; the standalone
  Go TUI assets are provided for debugging and compatibility.

## 中文说明

v0.5.0 是一个 **压缩正确性修复 + opt-in 实验能力** 的 minor 版本。默认压缩策略
仍然是 `stock`，没有切换默认行为。

### 主要变更

1. **默认修复压缩正确性**

   - 压缩读取最新事件窗口，而不是最老的 10,000 条事件；长会话不再丢掉当前指令。
   - 当前 `user_message` 永远保留；无法保留时 fail-closed。
   - state 与 summary 使用独立预算，摘要截断不会删除 state。
   - ledger 记录与触发阈值同单位的 pre/post token 数，并记录摘要 usage。

2. **opt-in 实验能力**

   - `BABEL_O_COMPACT_MODE=stock|noop|adaptive`，默认 `stock`；
     `BABEL_O_COMPACT_DECISION_LOG` 可记录 JSONL 决策。
   - adaptive 支持 payback 准入、T1 可逆驱逐、SHA-backed grounding。
   - 确定性 digest、按窗口缩放的摘要预算、cache token 映射、tail 边界。
   - summary cache、摘要模型覆盖、realized payback、forced percent。
   - faithful digest：extractive、verbatim anchors、不递归压缩；默认关闭。
   - cache-aware 93/80：默认关闭，验证未证明成本收益。
   - retrieval 指针：原型，不推荐生产使用。

3. **Nexus 端口修复**

   - 不再把任意 2xx `/health` 当作 Nexus；端口被非 Nexus 服务占用时自动切换到
     相邻空闲端口，并打印提示。
   - `bbl go --nexus-port-scan-attempts <n>` 限制扫描次数。

4. **评测专用 provider**

   - 包含 eval-only 的 `kimi-coding/k3` provider/model 条目，仅用于压缩评测，
     不是默认 provider，也不构成支持承诺。
